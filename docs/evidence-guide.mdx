This guide explains how to build `evidence.json` for the EATGF Engine without schema errors.

<DocSectionHeader number="01" label="Supported Status Values" description="Only the following status values are accepted by the engine." />

- `COMPLIANT`
- `NON_COMPLIANT`
- `PARTIAL`
- `NOT_TESTED`

Any other value fails fast during evaluation.

<DocSectionHeader number="02" label="Evidence File Structure" description="Each key must map to a valid control ID from registry_v1.1.json." />

```json
{
  "EATGF-EDM-GOV-01": {
    "status": "COMPLIANT"
  },
  "EATGF-DSS-VULN-01": {
    "status": "NON_COMPLIANT"
  }
}
```

<DocSectionHeader number="03" label="Recommended Workflow" description="Prepare evidence incrementally, then run the engine once the file is consistent." />

1. Start with `docs/templates/evidence.blank.json`.
2. Fill statuses for controls where evidence exists.
3. Keep missing controls absent or set them to `NOT_TESTED`.
4. Run:

```bash
python -m eatgf_engine.cli.main evaluate-compliance registry_v1.1.json org_profile.json evidence.json --output-json compliance_report.json
```

<DocSectionHeader number="04" label="Common Validation Failures" description="Typical issues that cause the engine to reject evidence input." />

- Unknown control ID in evidence
- Duplicate control key
- Invalid status value
- Invalid `evidence_metrics` type

<DocSectionHeader number="05" label="About evidence_metrics" description="How the optional field behaves in the current release." />

`evidence_metrics` is optional, ignored in v1.1 scoring, and reserved for future expansion (v1.2+).

<DocSectionHeader number="07" label="Validation Checklist" description="Final checks before running the engine and trusting the result." />

<DocChecklist label="Evidence quality gate">
  <DocChecklistItem>Evidence keys map to valid control IDs in `registry_v1.1.json`</DocChecklistItem>
  <DocChecklistItem>Status values are only `COMPLIANT`, `NON_COMPLIANT`, `PARTIAL`, `NOT_TESTED`</DocChecklistItem>
  <DocChecklistItem>No duplicate control IDs</DocChecklistItem>
  <DocChecklistItem>Optional `evidence_metrics` format is valid if provided</DocChecklistItem>
  <DocChecklistItem>Final run generates `compliance_report.json` successfully</DocChecklistItem>
</DocChecklist>
