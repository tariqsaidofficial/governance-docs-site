Use this guide to get an EATGF v1.1 governance workflow running quickly with deterministic outputs and audit-ready artifacts.

<DocSectionHeader number="01" label="Prerequisites and Scope" description="Ensure the following are in place before beginning." />

- Runtime: Python 3.11+
- Engine baseline: v1.1 deterministic evaluation
- Required output: `compliance_report.json`

Core references: [Engine Guide](./engine) · [Evidence Guide](./evidence-guide) · [Annex v1.1](./annex)

<DocSectionHeader number="02" label="Phase 1: Setup" description="Estimated time: 30 to 45 minutes." />

### Step 1: Review Core Artifacts

<DocChecklist label="Pre-flight reading">
  <DocChecklistItem>Read [Engine Guide](./engine)</DocChecklistItem>
  <DocChecklistItem>Read [Whitepaper v1.1](./whitepaper)</DocChecklistItem>
  <DocChecklistItem>Read [Annex v1.1](./annex)</DocChecklistItem>
</DocChecklist>

### Step 2: Prepare Input Files

<DocChecklist label="Input file selection">
  <DocChecklistItem>Choose org profile template: `docs/templates/org_profile.saas.json` or `docs/templates/org_profile.onprem.json`</DocChecklistItem>
  <DocChecklistItem>Start from `docs/templates/evidence.blank.json`</DocChecklistItem>
  <DocChecklistItem>Use `docs/templates/evidence.example.json` as reference</DocChecklistItem>
</DocChecklist>

### Step 3: Fill Evidence Correctly

<DocChecklist label="Evidence requirements">
  <DocChecklistItem>Follow [Evidence Guide](./evidence-guide)</DocChecklistItem>
  <DocChecklistItem>Use only supported statuses: `COMPLIANT` · `NON_COMPLIANT` · `PARTIAL` · `NOT_TESTED`</DocChecklistItem>
</DocChecklist>

**Phase 1 deliverables:** `org_profile.json` · `evidence.json`

<DocSectionHeader number="03" label="Phase 2: Run Engine" description="Estimated time: 10 minutes." />

### Step 4: Validate Registry

```bash
python -m eatgf_engine.cli.main validate-registry registry_v1.1.json
```

### Step 5: Evaluate Compliance

```bash
python -m eatgf_engine.cli.main evaluate-compliance registry_v1.1.json org_profile.json evidence.json --output-json compliance_report.json
```

**Phase 2 deliverables:** Deterministic terminal output · `compliance_report.json`

<DocSectionHeader number="04" label="Phase 3: Regression Safety Check" description="Estimated time: 5 minutes. Run local checks equivalent to the v1.1 CI logic." />

```bash
python -m eatgf_engine.cli.main evaluate-compliance registry_v1.1.json org_profile.json tests/ci_zero_evidence.json
python -m eatgf_engine.cli.main evaluate-compliance registry_v1.1.json org_profile.json tests/ci_invalid_status.json && exit 1 || exit 0
```

<DocCallout type="info" title="Expected Behavior">
Zero evidence returns score `0.0%` without crash. Invalid status fails fast.
</DocCallout>

<DocSectionHeader number="05" label="Validation Checklist" description="Confirm all deliverables before marking Phase 1–3 complete." />

<DocChecklist label="Final validation">
  <DocChecklistItem>Registry validation completed</DocChecklistItem>
  <DocChecklistItem>Evidence uses only supported statuses</DocChecklistItem>
  <DocChecklistItem>Compliance report generated</DocChecklistItem>
  <DocChecklistItem>Regression safety checks pass</DocChecklistItem>
</DocChecklist>

<DocCallout type="note" title="Operational Baseline Note">
This quick start is intentionally focused on v1.1 operational clarity. v1.2 planning (Strict Mode and BAI) starts only after this baseline is fully adopted.
</DocCallout>
